# 会话搬家（Session Move）

把一条会话「搬」到另一个项目目录下继续，是 DSH 原生做不到的事：会话的项目归属由创建时写死的
`SessionHeader.cwd` 决定，工作区账本按「header cwd 与项目路径严格相等」校验，而
`working_directory` 只能改**有效运行目录**、改不了归属。本插件因此采用「重建」：用目标目录做
header，把源会话已完成的完整历史（消息、推理、工具调用与结果、附件引用）连同 Agent 预设、模型
选择一起复制成一个新会话，再挂到目标项目上；源会话按需归档。

## 用法

1. **拖拽**：把指针停在会话行上，行尾会多出一个「移动到项目」抓手；拖住它，窗口底部会浮出
   「落地坞」，落在项目 chip 上即可。拖拽时按住 **Ctrl/⌘** 是复制（源会话保留），不按则是移动。
   普通地拖动行体仍然是 DSH 自带的排序手势，不会触发本插件。
2. **选择文件夹…**：目标目录还没登记成项目时用它，选中后由 Host 规范化并顺带登记。
3. **右键菜单 → 移动到项目…**：不拖拽也能用（键盘、触屏）；面板与落地坞是同一份逻辑，面板里可
   直接选移动还是复制。
4. 会话行的悬浮卡片里有一行「可拖到其他项目」提示，用来暴露这个手势。

移动成功后会自动刷新会话列表并打开新会话。源会话在「移动」模式下被归档；提示条在 10 秒内提供
**撤销**，会把源会话恢复并隐藏克隆。也可以稍后到归档视图 / 搜索里取消归档找回。如果源会话还有
正在运行的工作，Host 会拒绝归档，插件不替你中断对话，改为保留源会话并在提示里说明。

## 行为边界

- 复制的是**最后一个已完成回合**为止的前缀：正在进行的回合不进入新会话。
- 每次移动产生**新的会话 id**，磁盘上会多出一份日志（体积约为源会话前缀）。
- 后台任务、终端、定时任务、待审批/待回答的交互**不会**迁移。
- 若源会话用 `working_directory` 换过目录，新会话会被校正回目标项目路径（可能多一条目录变更上下文）。
- 置顶不随迁移继承；归档会清除源会话的置顶（DSH 既有语义）。
- 子代理会话、空白会话（尚无已完成回合）、以及目标就是当前项目时，操作会被拒绝并给出原因。

## 实现

- `index.js`：一条同源路由 `POST /api/session.relocate`。观察源会话
  （`sessionQuery.observeSession`）→ 取最后完成回合边界 → 生成 fork 种子 → `agents.create`
  （`meta.cwd` 指向目标项目、`isSeeded`）→ `workspace.attachSession` → 校正有效目录 →
  按模式 `archiveSession`。
- `fork-seed.js`：从 dsh-session 的 fork/repair 逻辑移植的纯函数（种子、合成 closer、未完成工具调用
  的保守错误结果）。插件刻意**不** import 任何 `@deepseek-ai/*` 包：profile 的模块解析不锚定正在运行
  的安装。
- `client.js`：拖拽识别、落地坞、项目选择模态框、i18n 与提示，全部只依赖 React 与主题 token。

## 限制

- 需要 Host 在运行（浏览器调用认证过的同源路由）。
- 迁移不是原子操作：克隆成功而归档失败时，结果是「复制 + 源保留」，不会被报告成失败。
- 会话 id 会变，所以外部引用（文档、书签、定时任务目标）仍指向旧会话。
